# Windows 1.3.13 — reliable installer completion and desktop restart

Fixed a real manual-install failure after the package had already been applied: NSIS places its native System.dll in the working directory, where Windows PowerShell could mistake it for the managed framework reference while compiling the normal-user restart helper. The helper now compiles from the loaded CLR's trusted directory with explicit framework references, restores both working directories afterwards, and preserves the normal-user token requirement.

Installation and restart are separate outcomes. Once migration and installed-version validation succeed, helper compilation, import or launch failures report successful installation with manual startup guidance rather than claiming that the update failed. No elevated application fallback is used. Settings and automatic-update preferences remain unchanged; an already-applied 1.3.12 can be opened from Start without reinstalling.

Added regression probes under actual Windows PowerShell 5.1 at 32 and 64 bits, including a native System.dll collision matching the installer directory, plus restart success/failure and directory-restoration checks. All three platform build gates remain required for publication; Linux 1.4.3 and macOS RC4 contain the corresponding post-install recovery changes. Existing tags/assets remain unchanged.

The saved Show Toast shortcut does not require a rapid double press: its next press requests Lyrics Plus after any delay while a toast remains visible. Hidden/expired toasts return the action to showing a toast; the configured duration and Alt+Shift+J destination are preserved.
