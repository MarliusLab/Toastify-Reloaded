# Linux 1.4.1

Click a toast's title or artist to open the displayed track in Spotify. The track URI comes from the same MPRIS metadata snapshot as the text. Only validated Spotify catalog identifiers are opened; native-handler failure falls back to a canonical Spotify HTTPS page. Missing/local/ad identifiers only activate Spotify. No title search or arbitrary external URL is launched.

Transient missing IDs no longer cause duplicate track-change notifications. Existing settings, themes, hotkeys and playback controls are preserved. DEB packages now declare `xdg-utils` for link opening; AppImage/tar users should install it on the host.

Packages: x64 AppImage, x64/ARM64 DEB and tar.gz, plus `SHA256SUMS.txt`.

Automated validation includes production-parser and launcher regression checks, native x64 headless self-tests, Xvfb startup and package checks. ARM64 is cross-built and inspected. Signed-in Spotify interaction, native ARM64, Wayland permissions, tray integration and Spicetify/updater behavior still require real desktop acceptance.
