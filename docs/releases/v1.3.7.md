# Windows 1.3.7 — detection and update progress

Fixes startup version fields remaining on “…” when an automatic update is waiting. Spotify and Spicetify are detected independently before the automatic update. Desktop/Store Spotify and Spicetify outside the inherited PATH are supported, with bounded background probes.

The updater now shows bytes and percentage when the server provides the total size, plus separate verification and Windows-permission stages. Downloads have idle/total limits, can be canceled before the elevation handoff, and remove partial files on failure. A canceled UAC request is reported and can be retried.

After Toastify closes, the installer shows its real installation progress. Update launches skip the normal wizard pages; the app restarts with the existing minimized preference. The installer waits on the exact original process and refuses to replace a still-running executable after timeout. Existing user settings are preserved.

Packages: `ToastifyReloaded-Setup-win-x64.exe`, `ToastifyReloaded-Setup-win-arm64.exe`, and `SHA256SUMS-Windows.txt`.

If an older installation is already stuck updating, close Toastify from its tray menu and run this release's installer manually. The running 1.3.5/1.3.6 updater cannot acquire the fix until the new version is installed.
