# Linux 1.4.4 — visible toast remains actionable during exit

The configured Show Toast shortcut requests Lyrics Plus whenever a toast remains visible, including during fade/slide out. An accepted request interrupts the old exit generation, keeps the same toast alive while pending and resumes its configured close after the action settles. Entry/exit completion cannot prematurely cancel navigation. Multiple-toast ownership, repeated-input serialization, explicit-close cancellation and hidden-toast refusal are covered by real timed-window regression tests.

The hotkey route is explicit and preserves the existing X11 key-release and Wayland portal-deactivation paths without adding a requirement to release Ctrl between presses. Physical Wayland shortcut behavior still depends on the compositor/permissions; headless tests do not replace that acceptance. Clicks, playback controls, settings and the separate current-track action are preserved.

Genuine full/delta package updates and prior installation/restart fixes are retained. All three platform builds and packaging gates must pass at the same source before publication; existing tags/assets remain unchanged.
