# Windows 1.3.14 — delayed Show Toast with Ctrl held

Fixed the actual Ctrl+Up workflow: keeping Ctrl down between the two presses no longer consumes the Lyrics Plus request after a 1.5-second modifier-release timeout. The saved Show Toast action now uses a dedicated fixed-URI path that waits for the primary key and mouse buttons to release, while allowing held modifiers. Click/Enter and the separate Alt+Shift+J Now Playing action retain their stricter input guards. No playback command, synthetic key event or track URI is sent by the Lyrics action.

A still-visible toast can now accept the action during fade/slide out. The old animation completion is invalidated, the same toast remains alive during navigation and it resumes its configured exit afterwards. Entry completion cannot restart expiration during a pending action. Settings, configured shortcuts, duration, appearance and playback functions are preserved.

Regression tests reproduce the reported failure on the real GlobalHotkeyService→ShowTimed→window→service path: two seconds between Ctrl+Up presses, Ctrl held throughout, primary-key release and a pending opener beyond the old fade deadline. Linux 1.4.4 and macOS RC5 include equivalent routing/lifetime fixes and real headless window tests. Publication requires all three main builds at the same source; prior tags/assets remain unchanged.
